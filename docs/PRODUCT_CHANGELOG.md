# 产品迭代记录

## v0.2：可直接演示与审核反馈

依据：代码审查与自动化验收发现的缺口，不是用户访谈反馈。

| 观察到的问题 | 产品取舍 | 改动 | 验证 |
| --- | --- | --- | --- |
| 新克隆仓库缺少评分 CSV，工作台启动后停止 | 优先降低作品集体验门槛 | 增加冻结案例演示，明确分层抽样边界 | Streamlit 应用测试 |
| 草稿只在生成按钮所在的一次运行显示 | 先保证完整审核任务 | 用会话状态保留原稿、支持人工编辑 | 生成—编辑—保存—重载测试 |
| 日志只保存状态与备注 | 优先保留审核依据 | 保存原稿、修改稿、反馈和前后状态 | 存储与迁移测试 |
| 多人修改会覆盖最新状态 | 拒绝静默覆盖 | 保存时检查版本，提供重新加载 | 冲突测试 |
| schema 有效但 ID/动作/引用仍可能不匹配 | 增加确定性校验，保留人工事实审核 | 校验 ID、标签、动作、政策与来源路径 | 控制校验测试 |
| 真实提供者配置即被标为“比较”，未区分失败 | 明确运行边界与成本未知 | 记录成功数、用量、价格及单提示词/比较范围 | 假客户端与 CLI 验证 |
| 未约束的 Arrow 版本可能与 NumPy 1.x 环境不兼容 | 保持现有 NumPy / 模型环境 | 显式约束 Arrow，并在锁定环境中测试 | 应用回归测试 |

本次没有重新训练模型、改变已提交性能结果、执行真实付费模型比较或开展用户研究。

## 后续候选

1. 配置真实模型，先做 5 例 smoke，确认日志和错误处理，再冻结版本完成对比。
2. 收集真实失败案例，人工核对数字代理无法发现的语义错误。
3. 执行代理用户试用，依据记录选定一项改进并复测。
4. 有实际部署需求时再考虑身份权限、状态审批、敏感字段脱敏与企业系统集成。

上述候选不作为已完成简历成果。
